# 特化 SIMD 对基准的贡献（A/B）

问题：`bench/compare` 里那些好看的倍数，有多少来自**为这几个程序写的**
循环形状模板，而不是通用代码质量？这份记录就是回答这个的。

## 机制

编译器里有两条向量化路径，默认值相反：

| 路径 | 实现 | 判据 | 默认 |
|---|---|---|---|
| 特化 SIMD | `src/codegen_simd*.cpp` | **固定 IR 操作码模板**（reduction / int map / nbody pair / pair 力循环），逐条比对指令序列 | **开** |
| 通用自动向量化 | `src/codegen_vect.cpp` | 认任意可数循环的 map/reduction | **关** |

模板里没有名字匹配、没有源码文本匹配、也没有 benchmark 里的字面常量 ——
但模板是照着这几个程序的循环体写出来的，形状不同就不触发。

## 测量方法

同一个二进制、同一份 `.py`，只改 `PYADAMAS_SIMD=0` 重新 `--rebuild` 编译；
两个产物**交替**跑（A,B,B,A…）各 6~12 轮取最小值，抵消系统漂移。
测量时间 2026-11-22，机器多租户，单次运行本身有 ±2 倍抖动，所以看**方向**
和**量级**，不要看小数点。

## 结果

| 用例 | SIMD 开 | SIMD 关 | 关掉后的代价 | 结论 |
|---|---|---|---|---|
| `matmul` | 5.0–5.8 ms | 22.2–23.9 ms | **慢 3.8–4.7×** | 收益几乎全来自特化路径 |
| `spectral_norm` | 13.9–26.4 ms | 53.4–56.0 ms | **慢 2.0–4.0×** | 同上 |
| `nbody` | 18.1 ms | 33.0–39.5 ms | **慢 1.8–2.2×** | 同上 |
| `fannkuch` | 6.4–11.7 ms | 7.9–14.7 ms | 噪声内（符号都不稳定） | 无结论 |
| `sieve` | 16.2–28.5 ms | 26.3–27.2 ms | 噪声内 | 无结论 |
| `fib` | 19.2–31.9 ms | 19.2–32.0 ms | 噪声内 | 无结论 |
| `binary_trees` | 4.64 ms | 4.65 ms | 无差异 | 无 |
| `mandelbrot` / `nqueens` / `fasta` / `collatz` / `wordfreq` | — | — | 未测出稳定差异 | 无结论 |

## 怎么读这张表

1. `matmul`（76.9×）、`spectral_norm`（104.7×）、`nbody`（68.7×）——**结果表里
   最漂亮的三行，正是特化 SIMD 承包的**。把这条路径关掉，它们掉到和 Go/C++
   同一量级甚至更慢。
2. 反过来，`RESULTS-0.383.md` 里"明显偏慢"的 9 个里，`sieve`/`wordfreq` 是
   今天新写的、**从没被优化过**的用例，落在 Go 的 0.34×/0.47×。这个数字才是
   「没有形状模板帮忙时」的真实水平。
3. 两个数字的差距就是「拟合」的规模：**被模板覆盖的循环快 2-4 倍，没覆盖的
   慢 2-3 倍**。

## 这算不算作弊

不算违规，但确实该披露：

- 判据是 IR 结构，不是程序名；任何写成那个形状的代码都会吃到，这点是干净的。
- 但「模板照着这几个程序写」意味着**形状稍有不同就退化**，这是拟合，不是
  通用的代码质量提升。
- 更该改的是默认值：通用向量化（`codegen_vect.cpp`）默认**关**，特化模板默认
  **开**。想要通用性能，默认该反过来。

## 建议

1. 结果表同时给两列：默认管线、以及 `PYADAMAS_SIMD=0` 的「通用管线」。后者
   才是可外推的水平。
2. 新加基准（本次的 `collatz`/`sieve`/`wordfreq`）写完后**先不要针对它们调优**，
   让它们保持为「未拟合对照组」。
3. 中期：把 `codegen_vect.cpp` 做成默认路径，特化模板逐步退化成它的补充。
