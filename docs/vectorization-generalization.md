# 向量化：从「给基准特化」到「泛化」

> 0.384 起：**特化 SIMD 默认关**（`PYADAMAS_SIMD=1` 才开，只作对照），
> **通用向量化默认开**（`PYADAMAS_VECT=0` 才关）。
>
> 理由：`codegen_simd*.cpp` 是照着 `bench/compare` 里几个程序的循环体写出来的
> 固定 IR 操作码模板 —— 形状不完全一致就不触发。把它放进默认管线，等于把
> 「在靶子上量出来的性能」当成「通用性能」卖给用户，这是欺骗。
>
> 代价是诚实的：下面第一节就是代价的具体数字。

## 1. 关掉特化之后的代价

同一份 `.py`，只改 `PYADAMAS_SIMD` 重新 `--rebuild`，两个产物交替跑 10 轮取最小值：

| 用例 | 新默认（通用 vect） | 旧默认（特化 simd） | 倍率 |
|---|---|---|---|
| `matmul` | 13.04 ms | 2.82 ms | **4.62× 慢** |
| `spectral_norm` | 58.10 ms | 12.85 ms | **4.52× 慢** |
| `nbody` | 36.61 ms | 8.15 ms | **4.49× 慢** |
| `sieve` | 20.13 ms | 15.99 ms | 1.26× 慢 |
| `fasta` | 1.97 ms | 1.87 ms | 噪声内 |
| `collatz` | 28.46 ms | 28.34 ms | 噪声内 |

中位数与最小值差 2 倍是这台机器的常态，所以上表用最小值、并且交替测量。

这 4.5× 就是「泛化欠账」的量化值 —— 泛化工作要还的就是它。

## 2. 通用向量化现在到底覆盖了什么

拿 `PYADAMAS_VECT_DBG=1` 跑 12 个基准，统计实际触发次数：

| 用例 | 触发的循环数 |
|---|---|
| `matmul` | **1**（内层 k 循环） |
| 其余 11 个 | **0** |

也就是说：**通用向量化在这套基准上的适用面是 1/12**。特化模板之所以能赢 4.5×，
正是因为它把那 11 个里的 3 个用「精确形状」硬编码了。

## 3. 差距在哪：逐条定位

`codegen_vect.cpp` 的头注释把它的适用范围写得很清楚：可数 for、体是纯算术
表达式 DAG、下标只认 `j+常量`、**无调用**、无 `store.global`。拿这五条去卡：

| 基准 | 卡在哪一条 | 说明 |
|---|---|---|
| `matmul` | 下标只认 `j+常量` | 已能匹配内层 k 循环；但 `b[k*N+j]` 是 stride-N，覆盖不了整段 |
| `spectral_norm` | 无调用 + 下标 | `s += eval_a(i,j) * a[j]`，`eval_a` 里有 `//`（整数除法）和 `(i+j)*(i+j+1)` |
| `nbody` | 无调用 | 内层有 `sqrt` / 除法、多个累加器、四个分量的位置更新（待精确定位） |
| `sieve` | 可数 for + 步长 | 内层 `q += p`，步长不是 1 |
| `collatz` / `mandelbrot` | 可数 for | 都是 `while` 且退出条件依赖数据 |
| `fib` / `nqueens` / `binary_trees` | 可数 for | 递归为主，没有可向量化的循环 |
| `fasta` / `wordfreq` | 可数 for + 无调用 | 伪随机状态推进 / 字典操作，本来就不适合 SIMD |

值得注意的是 `spectral_norm`：试过 `PYADAMAS_INLINE_OPT=1` 先内联再向量化，
**触发数仍然是 0**。所以它的瓶颈不是「调用挡住了分析」，而是 `eval_a` 里的
`(i+j)*(i+j+1)//2` —— 整数乘法链 + 整数除法，通用向量化的表达式分类器直接放弃。
这说明「接内联」是必要但不充分的一步。

## 4. 泛化路线（按「收益/成本」排序）

### P0 · 整数除法的强度削减 —— **已完成（0.385）**

三条闭式，对**全 int64** 成立：

| 运算 | 式子 | 指令数 |
|---|---|---|
| `x // 2^k` | `sarq $k`（算术右移就是 floor 除法） | 1 |
| `x % 2^k` | `andq $(2^k-1)`（补码下与 CPython 逐位相同） | 1 |
| `x / 2^k` | `(x + ((x>>63) & (2^k-1))) >> k` | 5 |

原来 floor 借用了 trunc 的式子再算余数修正，16 条 + 一个数据相关分支。
定宽整数（`u8`/`i16`/`u64`…）另外走 `codegen_int_fixed.cpp`，槽内值一律非负，
`//`、`%` 同样退化成一条 `shrq` / `andq`（0.386）。

**一个重要的否定结论**：这里不能用「被除数非负」来省指令。本语言 `int` 溢出
是**回绕**的（`docs/compatibility.md:11`），`(i+j)*(i+j+1)` 随时可能变负，
`shrq` 会算错。`sarq`/`andq` 不需要任何前提，所以这条是通用优化。

但 P0 没有提高向量化触发数（仍是 1/12）—— 它降的是**标量循环里**的除法成本。

### P1 · 仿射下标分析（设计已定，未实现）

当前下标模型只有 `index_off()`：**`j + 常量`**，其它一律 `Fail`。要覆盖
`matmul` 内层，需要 `C·j + 不变量 + 常量`：

```python
for k in range(N):
    s += a[i*N + k] * b[k*N + j]   # 前者 C=1、偏移 i*N；后者 C=N、偏移 j
```

改动分四块（都在 `codegen_vect.cpp`）：

1. **分析**：`index_affine(v)` 返回 `{coef, inv_vreg, off}`，`coef==1` 时退化
   成现有形态；`coef` 必须是编译期常量且 > 0。
2. **守卫**：现在只查 `len >= n + maxoff`；跨步要查 `len >= coef*(n-1) + inv + off + 1`，
   并且 `coef*2` 的配对访问要 `coef*(j+1)+inv+off < len`。
3. **装载**：`coef==1` 用 `movupd`；`coef>1` 只能 gather —— SSE2 没有 gather，
   得两次 `movsd` + `unpcklpd`（2 条装载 + 1 条打包，省掉 2 条 mul/add）。
4. **别名/依赖**：同对象读写判据要按 `coef` 重算「跨 lane 无依赖」，`coef>1`
   时「同偏移原地 map」不再成立，一律保守跳过。

**代价估计**：约 300 行改动 + 重跑 6 个 vect 用例的负例。收益预估 2–4×（参照
特化模板在 `matmul` 上的 4.6×，通用版没有分量轴融合，打个折）。

**为什么不半做**：只支持「`j + 不变量`偏移」在 `matmul` 上无效 —— 两个操作数
必须同时可向量化，`b[k*N+j]` 不支持整段就还是标量。所以这条要一次做完整。

### P2 · 让 vect 的循环形状更宽

#### while 循环 —— **已完成（0.387）**

`for` 形状是 cond/body/incr 三块；手写的 `while i < n: …; i += 1` 降成两块的
cond/body，增量在体块尾部三条。向量化器只认前者，后者整段跳过 —— 而它是
**手写数值代码里最常见的写法**。

`simd_while_shape_ok()` 补了这条路径：识别 cond/body 两块 + 体块尾部
`load sJ / add 1 / store sJ / jump cond`，把它等价于 for 形状处理（增量三条在
角色判定里标成 Skip，由向量循环自己维护 j）。

实测（4096 元素、20000 轮、算力密集型归约，交替 9 轮取最小）：

| 形态 | 向量化 | 标量 | 加速 |
|---|---|---|---|
| `while` | 118.84 ms | 212.23 ms | **1.79×** |
| `for` | 119.12 ms | 225.61 ms | 1.89× |

两者已经等价（差 0.2%）。回归：`tests/run/457_vect_while.py`（归约、map、边界
n=0/1/2/3/5、负值、以及「体里有调用 → 保守 fallback」）。

#### 步长 != 1 —— **不可行，放弃**

原计划是让 `sieve` 的 `q += p` 可向量化。实测走不通，三个理由：

1. **步长是运行期值**（`p` 是循环不变量但不是编译期常量），而 x86 寻址的
   scale 只有 1/2/4/8 —— 超过 8 必须每条 lane 单独算地址，向量化收益归零；
2. `sieve` 的变量还是**模块级全局**（`load.global` / `store.global` + RC 调用），
   向量化器明确拒绝 `store.global`；
3. 就算把代码挪进函数，触发数**仍然是 0**（实测），因为那条循环是「跨步写常量」，
   本来就没有 packed store 可用。

结论：这条从路线图里划掉。`sieve` 那类循环该靠别的手段（例如 stdlib 层的
`list.__setitem__` 批量接口），不是向量化。

### P3 · 4-lane（AVX2）

现在只有 SSE2 2-lane，理论上限就是 2×；模板能到 4.5× 有一部分来自更宽的展开。
这条代码量最大，但它对**所有**能向量化的循环都有效，是唯一能整体抬高的手段。

### P4 · 删掉特化模板

等 P0–P3 把 `matmul`/`spectral_norm`/`nbody` 重新吃到 2× 以上，就删 `codegen_simd*.cpp`。
在此之前保留它们作**对照基线**（`PYADAMAS_SIMD=1`），但绝不进默认管线。

## 5. 测量纪律（这次事故的直接教训）

1. **发布数字只能来自默认管线**。任何 `PYADAMAS_*` 非默认开关跑出来的表，
   要么标注清楚，要么不许当性能结论。
2. **新增基准写完不许针对它调优**。`collatz`/`sieve`/`wordfreq` 就是留作
   「未拟合对照组」的 —— 它们的倍数才是可外推的水平。
3. **结果表同时给两列**：默认管线、以及 `PYADAMAS_SIMD=1` 的对照。差距缩小
   到 1.3× 以内，才算泛化成功。
4. **单轮不可用**。这台机器同一二进制能差 2 倍，必须多轮交替取最小。
