# 向量化：从「给基准特化」到「泛化」

> 0.384 起：**特化 SIMD 默认关**（`PYADAMAS_SIMD=1` 才开，只作对照），
> **通用向量化默认开**（`PYADAMAS_VECT=0` 才关）。
>
> 理由：`codegen_simd*.cpp` 是照着 `bench/compare` 里几个程序的循环体写出来的
> 固定 IR 操作码模板 —— 形状不完全一致就不触发。把它放进默认管线，等于把
> 「在靶子上量出来的性能」当成「通用性能」卖给用户，这是欺骗。
>
> 代价是诚实的：下面第一节就是代价的具体数字。

## 1. 关掉特化之后的代价

同一份 `.py`，只改 `PYADAMAS_SIMD` 重新 `--rebuild`，两个产物交替跑 10 轮取最小值：

| 用例 | 新默认（通用 vect） | 旧默认（特化 simd） | 倍率 |
|---|---|---|---|
| `matmul` | 13.04 ms | 2.82 ms | **4.62× 慢** |
| `spectral_norm` | 58.10 ms | 12.85 ms | **4.52× 慢** |
| `nbody` | 36.61 ms | 8.15 ms | **4.49× 慢** |
| `sieve` | 20.13 ms | 15.99 ms | 1.26× 慢 |
| `fasta` | 1.97 ms | 1.87 ms | 噪声内 |
| `collatz` | 28.46 ms | 28.34 ms | 噪声内 |

中位数与最小值差 2 倍是这台机器的常态，所以上表用最小值、并且交替测量。

这 4.5× 就是「泛化欠账」的量化值 —— 泛化工作要还的就是它。

（上表是 0.384 关特化当时的数字；后续覆盖进展见 §2、§2.1。）

## 2. 通用向量化现在到底覆盖了什么

拿 `PYADAMAS_VECT_DBG=1` 跑 12 个基准，统计实际触发次数（0.411 之后、默认管线）：

| 用例 | 触发的循环数 | 覆盖原因 |
|---|---|---|
| `matmul` | **4** | P1 仿射下标（coef>1 gather）+ P3 AVX2 4-lane 整数路径 |
| `spectral_norm` | **2** | P5：整数 floor 除法（2 的幂除数）+ 归纳变量参与算术 |
| `nbody` | **1** | 0.411 起：`energy` 内层（sqrt + float Sub 归约 + coef==0 广播装载）；`advance` 仍 0 |
| 其余 9 个 | **0** | 见 §3 |

合计 **7 个循环 / 3 个基准**。0.384 关特化时这个数字是 **1/12**（只有 matmul 内层），
P1/P3/P5 之后涨到 6 个，0.411 的 coef==0 广播装载补上 nbody 的 `energy` 内层。

特化模板之所以当年能赢 4.5×，正是因为它把那 11 个里的 3 个用「精确形状」硬编码了；
通用路径现在的目标不是覆盖全部（`fib`/`nqueens`/`binary_trees` 这类递归为主、
`sieve` 是运行期步长，本来就不适合 SIMD），而是把「可覆盖但被保守判据挡住」的补上。

### 2.1 当前能力边界

**已支持**（判据都只看 IR 结构，无基准名/字面量特化）：

| 能力 | 引入版本 | 说明 |
|---|---|---|
| 仿射下标 `coef·j + inv + off` | 0.388（P1） | `coef==1` 用 `movupd`；`coef>1` 用两次 `movsd` + `unpcklpd` + 跨步计数器 `K` |
| while 循环形状 | 0.387（P2） | cond/body 两块 + 体尾三条增量，等价于 for |
| 整数 4-lane（AVX2） | 0.389（P3） | 只做整数 map/reduction；运行时派发 `pa_cpu_avx2` |
| 整数 floor 除法 / 归纳变量参与算术 | 0.391（P5） | 除数是 2 的幂常量时合成算术右移；j 当 VecI 用 |
| `math.sqrt`（CallRt） | 0.408（B2） | 2-lane `sqrtsd`；负数/NaN 守卫跳标量尾（ValueError 时机不变） |
| float Sub 归约（`s -= x`） | 0.409（B3） | 按 lane 顺序 `subsd`，与标量逐位一致；int Sub 仍保守标量 |
| `coef==0` 不变下标元素装载 | 0.411（B4） | 一次 `movsd` + `movlhps` 广播成 `[v,v]`；一次性区间守卫 |

**已知不支持**（一律保守跳过，不会生成错代码）：

- **`coef>1` 的 scatter 写**（`IndexStore` 仍要求 `coef==1`）：SSE2 没有 packed scatter，
  且 nbody 的 `b[i*7+c] = ...` 这类跨步写即使逐 lane 发也没有收益；
- **同一数组的混合偏移读写**（读 off 0/1/2、写 off 3/4/5 之类）：别名分析证不出
  逐元素原地，整段标量 —— 这是 nbody `advance` 内层的主要阻塞；
- **嵌套循环形状**：向量化器只认 cond/body/incr 三块直线体，外层循环的 body 跳的是
  内层 preheader 而不是 incr，直接跳过（nbody `advance` 的 steps/i 外层、`energy` 外层）；
- **非 2 的幂除数**的整数 `//` / `%`（P5 只做 2 的幂常量）；
- **AVX2 没有广播装载路径**：含 `coef==0` 访问的循环整段留给 SSE2 2-lane；
- 运行期乘法进仿射（`2*(M+j)`、`j*N` 且 N 是运行期值）、`j-1`、移位、负系数；
- 浮点 4-lane（语义上刻意不做：浮点归约承诺与标量逐位一致，必须逐 lane 串行加）。

## 3. 差距在哪：逐条定位

`codegen_vect.cpp` 的头注释（0.384 时代）把适用范围写得很清楚：可数 for、体是纯
算术表达式 DAG、下标只认 `j+常量`、**无调用**、无 `store.global`。这五条后来被逐条
放宽（P1/P3/P5 + 0.408–0.411），现在的实际卡点：

| 基准 | 现状 | 说明 |
|---|---|---|
| `matmul` | ✅ 已覆盖（4 触发） | P1 仿射下标（`coef>1` gather）+ P3 AVX2 4-lane 整数路径 |
| `spectral_norm` | ✅ 已覆盖（2 触发） | P5：`eval_a` 里的 `//`（2 的幂除数）+ `(i+j)*(i+j+1)` 的归纳变量算术 |
| `nbody` | 部分覆盖（1 触发） | `energy` 内层已覆盖（sqrt + Sub 归约 + coef==0 广播装载）；`advance` 内层/位置更新仍卡 `coef=7` scatter 写 + 同数组混合偏移，外层是嵌套循环 |
| `sieve` | 可数 for + 步长 | 内层 `q += p`，步长不是 1 |
| `collatz` / `mandelbrot` | 可数 for | 都是 `while` 且退出条件依赖数据 |
| `fib` / `nqueens` / `binary_trees` | 可数 for | 递归为主，没有可向量化的循环 |
| `fasta` / `wordfreq` | 可数 for + 无调用 | 伪随机状态推进 / 字典操作，本来就不适合 SIMD |

值得注意的是 `spectral_norm`：试过 `PYADAMAS_INLINE_OPT=1` 先内联再向量化，
**触发数仍然是 0**。所以它的瓶颈不是「调用挡住了分析」，而是 `eval_a` 里的
`(i+j)*(i+j+1)//2` —— 整数乘法链 + 整数除法，通用向量化的表达式分类器直接放弃。
这说明「接内联」是必要但不充分的一步。

## 4. 泛化路线（按「收益/成本」排序）

### P0 · 整数除法的强度削减 —— **已完成（0.385）**

三条闭式，对**全 int64** 成立：

| 运算 | 式子 | 指令数 |
|---|---|---|
| `x // 2^k` | `sarq $k`（算术右移就是 floor 除法） | 1 |
| `x % 2^k` | `andq $(2^k-1)`（补码下与 CPython 逐位相同） | 1 |
| `x / 2^k` | `(x + ((x>>63) & (2^k-1))) >> k` | 5 |

原来 floor 借用了 trunc 的式子再算余数修正，16 条 + 一个数据相关分支。
定宽整数（`u8`/`i16`/`u64`…）另外走 `codegen_int_fixed.cpp`，槽内值一律非负，
`//`、`%` 同样退化成一条 `shrq` / `andq`（0.386）。

**一个重要的否定结论**：这里不能用「被除数非负」来省指令。本语言 `int` 溢出
是**回绕**的（`docs/compatibility.md:11`），`(i+j)*(i+j+1)` 随时可能变负，
`shrq` 会算错。`sarq`/`andq` 不需要任何前提，所以这条是通用优化。

但 P0 没有提高向量化触发数（当时仍是 1/12）—— 它降的是**标量循环里**的除法成本。

### P1 · 仿射下标分析 —— **已完成（0.388）**

下标模型从 `j + 常量` 扩成 **`coef·j + inv + off`**（`coef > 0` 编译期常量、
`inv` 循环不变 int 值、`off` 编译期常量）。新增 `src/codegen_vect_affine.cpp`
（230 行），`codegen_vect.cpp` 改 165 行接入。

| 块 | 做法 |
|---|---|
| 分析 | `vect_affine_index()`：j → `{1,无,0}`；`Add` 累加；`Mul` 常量且无 inv 才折系数（运行期乘法不折）；跨块 `Mov` 取**自己**的 home |
| 守卫 | `coef*(n-1) + inv + off < len` 且 `inv + off_min >= 0`，每步 `jo` 溢出即跳标量 |
| 基址 | `base = data + inv*8`（循环入口一条 `leaq`） |
| 装载 | `coef==1` → `movupd`；`coef>1` → 两次 `movsd` + `unpcklpd`（SSE2 无 gather），配合跨步计数器 `K`（每轮 `+= coef*16`） |
| 写出 | 只支持 `coef==1`（不做 scatter） |

**实测（matmul，交替 9 轮取最小）**：

| 配置 | 用时 |
|---|---|
| 两者都关（纯标量） | 15.28 ms |
| 默认（通用 P1） | **3.54 ms（4.3×）** |
| 默认 + 特化 SIMD | 2.78 ms |

通用路径离特化只差 **1.27×** —— 按第 5 节「1.3× 以内算泛化成功」的标准，
`matmul` 这一项达标了，特化模板对它已经多余。但 `spectral_norm`/`nbody` 仍然
完全依赖特化（它们分别卡在 `eval_a` 内联和 sqrt/多累加器上），所以 P4 还不能做。

**没覆盖的**（都保守跳过，不会生成错代码）：

- `IndexStore` 的 `coef > 1`（scatter，没有 packed 指令，也不划算）；
- 运行期乘法进仿射（`2*(M+j)`、`j*N` 且 N 是运行期值）；`j-1`、移位、负系数不认；
- `Convert`（i64→f64）：`j+常量` 走快速路径，其余落回通用 `VecI` 折算
  （不变量广播 + `paddq` + `cvtdq2pd`；b316646 起就有，0.407 修掉了快速路径的
  disp32 上界，大常量 + j 不再汇编失败）；
- 同一数组多个不同 inv 的**写**：证不出相等就整段标量；
- 基址 + 计数器必须塞进 `rdi/rdx/rcx`（+`rsi`），放不下放弃；
- 浮点仍是 2-lane SSE2（P3 的 AVX2 只做整数 4-lane）；含 `coef==0` 广播装载的
  循环也整段留给 SSE2（4-lane 没有广播装载路径）。

### P2 · 让 vect 的循环形状更宽

#### while 循环 —— **已完成（0.387）**

`for` 形状是 cond/body/incr 三块；手写的 `while i < n: …; i += 1` 降成两块的
cond/body，增量在体块尾部三条。向量化器只认前者，后者整段跳过 —— 而它是
**手写数值代码里最常见的写法**。

`simd_while_shape_ok()` 补了这条路径：识别 cond/body 两块 + 体块尾部
`load sJ / add 1 / store sJ / jump cond`，把它等价于 for 形状处理（增量三条在
角色判定里标成 Skip，由向量循环自己维护 j）。

实测（4096 元素、20000 轮、算力密集型归约，交替 9 轮取最小）：

| 形态 | 向量化 | 标量 | 加速 |
|---|---|---|---|
| `while` | 118.84 ms | 212.23 ms | **1.79×** |
| `for` | 119.12 ms | 225.61 ms | 1.89× |

两者已经等价（差 0.2%）。回归：`tests/run/457_vect_while.py`（归约、map、边界
n=0/1/2/3/5、负值、以及「体里有调用 → 保守 fallback」）。

#### 步长 != 1 —— **不可行，放弃**

原计划是让 `sieve` 的 `q += p` 可向量化。实测走不通，三个理由：

1. **步长是运行期值**（`p` 是循环不变量但不是编译期常量），而 x86 寻址的
   scale 只有 1/2/4/8 —— 超过 8 必须每条 lane 单独算地址，向量化收益归零；
2. `sieve` 的变量还是**模块级全局**（`load.global` / `store.global` + RC 调用），
   向量化器明确拒绝 `store.global`；
3. 就算把代码挪进函数，触发数**仍然是 0**（实测），因为那条循环是「跨步写常量」，
   本来就没有 packed store 可用。

结论：这条从路线图里划掉。`sieve` 那类循环该靠别的手段（例如 stdlib 层的
`list.__setitem__` 批量接口），不是向量化。

### P3 · 4-lane（AVX2）

**已完成（0.389），但只做整数路径。** 先量了上限再动手（同一份 C 内核只改
`-mavx2`）：

| 内核 | SSE2 | AVX2 | 倍率 |
|---|---|---|---|
| 整数归约 `s += a[i]*b[i]` | 95.66 ms | 45.28 ms | **2.11×** |
| 浮点归约 `s += a[i]*a[i]+0.5` | 59.61 ms | 45.20 ms | 1.32× |

**浮点路径刻意留在 2-lane**：我们的浮点归约承诺「与标量逐位一致」（保序），
每轮必须把 lane 拆成标量加，形成串行依赖链；4-lane 只会把链拉得更长。这不是
实现差距，是语义选择 —— gcc 能 packed 累加是因为 C 不承诺顺序。

实现：`src/codegen_vect_avx2.cpp`（298 行），整数 map / reduction 走 4-lane
ymm；**运行时派发**读 `pa_cpu_avx2`（构造函数里由 `__builtin_cpu_supports` 填，
初值 0 = 保守回退），非 AVX2 机器走原 SSE2 路径，不会 SIGILL。

`matmul` 的指令条数 **19,558,668 → 10,605,880（1.84×）**；SSE2 构建与运行期
回退都是 19.56M（差 0.14% = 派发那条 `cmpl`），证明回退分支真的走到了。

`PYADAMAS_AVX2=0` 同时是编译期（只发 SSE2）与运行期（强制回退）开关，用来
对拍两条路径 —— 已写进 modcache 清单，切开关必重建（否则会拿到另一条路径的
旧产物，实测踩过）。

没做：浮点 4-lane、AVX-512/8-lane、真·非 AVX2 实机验证（本机只有 AVX2，用
「编译期只发 SSE2」「运行期强制回退」「能力字节初值 0」三条覆盖）。

### P4 · 删掉特化模板

P3 落地后，`matmul` 上**特化反而更慢**（指令数，确定性口径）：

| 配置 | 指令数 | 相对纯标量 |
|---|---|---|
| 默认（通用 P1+P3） | 10,605,880 | **8.23×** |
| 打开特化 SIMD | 14,742,646 | 5.92× |
| 两者都关 | 87,326,649 | 1.00× |

原因是 `gen_block` 里的顺序：`if (!try_simd_vectorize(b)) try_vect_loop(b);` ——
特化先试，命中就轮不到通用路径。而特化是 2-lane + 分量轴硬编码，通用已经是
4-lane AVX2，于是**特化把更好的实现挡在门外**。

所以对 `matmul` 这类形态，P4 已经不是「等泛化追上」，而是「特化在拖后腿」。
但 `spectral_norm`/`nbody` 仍只有特化能覆盖，所以现在还**不能整体删**。

### P5 · 整数 floor 除法 + 归纳变量参与算术 —— **已完成（0.391）**

`spectral_norm` 的内层循环有两道坎，**我一开始只看见第二道**：

**第一道（真正的首因）**：`int_ok` 只收 `InvI`/`VecI`，`VK::J` 不在里面 —— 归纳
变量只要不当下标（而是参与算术），整个表达式就判 Fail。`float(j*j)`、
`float(i+j)` 都不向量化。修法：j 当 VecI 用，在首个算术使用点物化成 `[j, j+1]`
（`src/codegen_vect_jvec.cpp`，213 行；4-lane 物化 `[j..j+3]`）。

**第二道**：`BinKind::FloorDiv`。修法：除数是 2 的幂常量时接受，用 2 的补码合成
算术右移（SSE2/AVX2 都没有 64 位 lane 的 `psraq`）：

```
sign = psrlq(x, 63); sign = psllq(sign, 64-m); q = psrlq(x, m); q = por(q, sign)
```

`%` 则是 `pand $(k-1)`。判据只有「除数是不是 2 的幂常量」—— LLVM InstCombine /
GCC tree-vect 同口径，是**通用操作支持**，不是形状特判。

**还有一个必须同时修的正确性命门**：原来「含 j 的仿射式」一律折叠进寻址、不
发射，靠「J 不在 int_ok → 另作他用必 Fail」兜底。J 放行后 `i+j` 会被折成
`Role::Skip`，但它同时是 `(i+j)*(i+j+1)` 的操作数 → 发射期查无寄存器 →
半截汇编 + 悬空标签。改成「全部使用点都是下标操作数才折叠」。

结果：`spectral_norm` 触发数 **0 → 2**，-O2 指令数 **−16.37%**，12 个基准最大
回退 +0.15%。

`nbody` 那边当时是 sqrt/除法 + 多累加器 + 分量轴；后续 0.408–0.411 依次补了
sqrt、float Sub 归约、coef==0 广播装载，`energy` 内层现在能触发（1 个循环）。
`advance` 仍卡在 `coef=7` scatter 写 + 同数组混合偏移（big feature，未做）。

## 5. 测量纪律（这次事故的直接教训）

1. **发布数字只能来自默认管线**。任何 `PYADAMAS_*` 非默认开关跑出来的表，
   要么标注清楚，要么不许当性能结论。
2. **新增基准写完不许针对它调优**。`collatz`/`sieve`/`wordfreq` 就是留作
   「未拟合对照组」的 —— 它们的倍数才是可外推的水平。
3. **结果表同时给两列**：默认管线、以及 `PYADAMAS_SIMD=1` 的对照。差距缩小
   到 1.3× 以内，才算泛化成功。
4. **单轮不可用**。这台机器同一二进制能差 2 倍，必须多轮交替取最小。
