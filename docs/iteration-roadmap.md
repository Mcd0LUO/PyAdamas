# PyAdamas 下一阶段迭代路线图

> 2026-11-21 · 基线 0.356（`cd82e6f` 含接续文档提交）。版本号是候选，不为没过闸门的改动预留发布。本文给出下一阶段的排序；[性能迭代日志](optimization-roadmap.md#迭代日志自主执行记录) 保留历史结果。

## 推荐顺序

**BigInt 可发布 → 修通用引用泄漏 → 用 Fraction 验证精确整数的实际价值 → 用日常语料决定性能下一轮。** BigInt 当前是唯一在途实现。后续每项独立工作树、独立闸门，不把兼容性、修复和性能实验捆成一版。

| 轮次 | 要交付什么 | 过关条件 / 不做什么 |
|---|---|---|
| **1 · 0.357 候选：BigInt 最小可发布版** | 显式 `big`、超 `u64` 十进制字面量、算术/比较/移位、`unknown` 往返、常用内建与跨模块传递。先验证块 C，再闭合 D/E；将实际支持与拒绝行为写进落地文档。 | 共同语义与 CPython 对拍；预定差异各有单测，不混入“零差异”统计。新增带符号和边界转换、GC/异常路径；既有 38 个热基准 asm 完全相同，另查跨模块缓存和两种类型标签模式。默认 `int` 仍是 i64，不改溢出规则；容器键/排序若未实现，不得静默按指针当数值。 |
| **2 · 下一独立修复版：早返回漏 `dec`** | 在 lowering 使用最终槽所有权或等价机制补全释放。同时加 `return` 位于首次堆写之前、却在后续迭代执行的最小复现；覆盖零次迭代、借用槽、异常和正常出口，生成器/协程如不在修复范围则用负面用例钉住。 | 复现及 [`a2_config_parse`](../bench/daily/a2_config_parse.py) 的 `coerce()` 在 LSan 下干净，不引入多减/UAF。向用户明确请求**单独批准**预期汇编差异：逐条解释预期 `dec`，其余样本逐字不变；不直接更新整份基线。 |
| **3 · 精确算术首个用户功能：`Fraction`** | 用一个独立探针证明 `big` 字段、参数/返回、跨模块和 `%`/`//` 已足够支撑 Euclid gcd、符号归一化和精确比较。以 [`fractions.py`](../stdlib/fractions.py) 现有 API 为起点，先解决超过 int64 后静默回绕，不一次扩到 Decimal 或完整 CPython 构造器。 | 小整数旧用例不退；构造/约分/四则/比较/格式化/除零与 CPython 对拍，额外测输入能放入 i64、但中间乘积超 i64 的情况。字段公开类型或哈希口径若要变化须单列兼容性决策，不能搭车改。 |
| **4 · 性能轮：先重新测，再只押一个热点** | 按 [23 个日常语料](daily-corpus.md) 同窗复测短 CLI、配置、字符串/正则、CSV、数值。分别记冷 `build --rebuild`、模块缓存命中构建、纯运行，以及真实一次性总时长。另抽 realistic/经典用例查退化，不把旧数字当新基线。 | 若短脚本仍被构建支配，先拆前端/汇编/链接/缓存命中率，选占主导且收益可复现的一层；若产物复用场景由字符串/容器成本主导，先做在两类日常案都成立的 RC/查找取证。只在受影响真实语料的收益超过 A/A 噪声且两窗可复现时继续，否则留负面结果，不提交优化。 |

### BigInt 本轮边界

- 别把新 `big` 当成 CPython 的默认 `int`。手册已约定 `big + float` 截断浮点侧、`big ** 负指数` 抛 `ValueError`、显式窄化截断；混合比较则按精确值判断（含 NaN/无穷）。这些差异要和普通 CPython 对拍分开。
- `list[big]` 的值比较/排序、`dict`/`set` 键的值哈希另开专项。只有有等值异对象、同值跨类型键、一致的 `eq/hash` 和 RC/GC 回归，才宣称支持。若这些能力不阻塞 `Fraction`，不抢占第三轮。
- **发布阻塞已解除（`b714dd8`）**：纯动态路径按「全图模式」修好了，而不是写进限制。`Program::needs_dynamic_big` 由全图语法扫描求得（`big` 注解、`cast_big` 调用、超 u64 字面量），写入模块缓存键；该模式下 `unknown` 域的 `& | ^ ~ ** << >>` 走 `AnyBigBinary`/`AnyInvert` 的 BIG 分派，动态容器键用 `key_kind 9` 按值哈希/等值，并且强制保留堆注册表（探针依赖它）。静态可判定的 `big` 键仍编译期拒绝。
- 隔离的代价与剩余边界：模式是编译图级的，一个模块里出现 `big` 就整图走新路径（big 程序因此多建堆注册表）；纯动态的 `int(v)` 仍是 i64 截断、混合「静态 float + unknown」不做 big 提升、纯动态真除仍走 float 路径。
- 跨模块默认值/签名、热缓存与冷缓存、翻译单元中的永生字面量分别覆盖。字长、符号、NaN/无穷、负移位、零除、异常退出不能只靠运行时 fuzz 间接证明语言前端正确。

### 0.357 候选：已验证的推进

`big2`（`b714dd8`）已验证显式大数、基础动态算术、常用格式化，以及下面那一节的两个动态阻塞缺陷；分支保留，未合入主线。候选差分 351/0，普通和 ASan 套件各 371 通过，ASan+LSan 钉子 14/14 干净。旧行为对 0.356 独立复核：346 个运行语料全部编译成功、产物退出 0，stdout/stderr 逐字节一致；38 个热基准的入口汇编逐字节一致。跨模块 `u64` 上界与负超宽默认值已修，O0/O2 × 标签开关 × 冷/缓存命中共 8 组过关；亚正规真除也与 CPython 对拍一致。上述证据不覆盖下一节的动态域发布阻塞。

### 0.357 候选的两个动态阻塞（已修，`b714dd8`）

下面两个缺陷都只在**纯动态**（先擦成 `object` 再运算）路径上复现，六种配置（O0/O2 × 标签开关 × ASan）全部命中；修好后同样六种配置全部通过，并各留了回归（`tests/run/400_big_dynamic_ops.py`、`tests/run/401_big_dynamic_keys.py`、`tests/modules/66_big_dynamic/main.py`，随分支合入）。修法是按编译图启用的 `needs_dynamic_big` 模式，未使用 `big` 的程序生成 asm 仍是逐字节不变（0.356 主树 464 个 `.py` 实测全同）。

```python
def erase(v: big) -> object:
    return v

def low4(v: object) -> object:
    return v & 15  # 也应覆盖 **、<<、>> 和一元 ~

a: big = 18446744073709551623
x: object = erase(a)
y: object = erase(a + 1 - 1)
print(low4(x))
d: dict[object, int] = {}
d[x] = 41
print(y in d)
```

独立回归按上面的形状分别运行两例（第一例若抛异常不能阻止第二例执行），再按跨模块形状把 `low4` 和键操作移动到只声明 `big` 注解的辅助模块里，测 `-O0`/`-O2`、标签开关、冷构建与缓存命中。模式本身还有一条缓存不变量已经实测：非 `big` 程序先缓存 `plain` 模块后，`big` 程序会重新编译它而不是复用旧产物。

### 一次性短脚本的固定成本（实测，构建路径）

0.358 轮的做法是先取证再动手。绑核 24、多次重复稳定后的结论：

| 步骤 | 耗时 |
|---|---:|
| `pyadamas --help`（进程启动 + 动态库） | 1ms |
| `check`（词法/语法/类型） | 5ms |
| `ir -O2`（再加 IR 优化） | 11ms |
| `asm -O2`（再加 codegen，输出 313 行汇编） | 11ms |
| `build -O2`（模块缓存命中，含汇编+链接） | 38ms |
| `build -O2 --rebuild` | 52ms |
| 单独 `as`（3000 行汇编） | 8ms |
| 单独 `ld --gc-sections`（rt.o 1.0MB） | 9ms |

一个 313 行汇编的 hello-world 冷构建 52ms、热构建 38ms，而它自身的编译只要 2ms ——**固定成本约占 70~80%，与程序大小几乎无关**。拆开看：`as` 8ms + `ld` 9ms + 编译器自身 10~15ms，剩下的散在两次 `sh -c` 包装（实测各约 1ms）、缓存清单读写与临时文件收尾。

因此本轮**不提交微优化**：把 `std::system` 换成 fork/exec、把汇编喂给 `as` 的标准输入，单项都在 1~2ms 量级（约 2~5%），低于 A/A 噪声，且要动链接回退路径，风险不成比例。真正的量级改动只有两条，都属于架构级：内嵌汇编器/链接器，或「整程序产物缓存」（同源码+同选项+同工具链直接复用上次链接结果）——后者对首次运行无效，只帮重复构建，与「一次性脚本」的场景不符。

结论：**这条线在当前实现下没有性价比可取的优化**。若将来要把一次性脚本做到接近 CPython 启动开销，得按上面的架构方向立项，而不是继续在驱动层抠毫秒。
### 所有权修复为什么单列

[0.356 的取证](strfix-rc-early-return.md#根因编译器-lowering-早返回漏-dec通用-bug) 说明：同一条早返回在源码顺序上先于槽的首次堆写，但执行时可能已经跨过一次循环回边。用显式 `object` 槽加第二次迭代早退，在 0.356 独立复现了 1 个、120 字节的泄漏；关闭泄漏检测时输出仍与 CPython 一致。当前日常配置样本未单独报漏，因此它主要用来钉住已知的汇编变更位置，不能替代最小复现。

### 0.356 复测：一次性短脚本仍由构建支配

2026-11-21，同窗绑核 24、9 轮、运行每组 3 次取中位；[日常语料](daily-corpus.md) 23/23 与 CPython 3.14.4 的输出逐字节一致，双方退出码均为 0。类别中位数（ms）：

| 类别 | CPython 运行 | PyAdamas 冷构建（`--rebuild`） | PyAdamas 产物运行 |
|---|---:|---:|---:|
| 短 CLI / 配置 | 20.68 | 64.83 | 3.26 |
| 字符串 / 正则 | 53.57 | 69.29 | 17.80 |
| CSV | 25.59 | 91.47 | 6.66 |
| 数值 | 40.11 | 68.65 | 4.69 |

本次“冷”指强制重新构建，不是清空系统页缓存；未测模块缓存命中或端到端总耗时。因此这组数字用于选方向，不用于承诺提速。下一次性能轮优先拆短脚本构建路径，不先押更宽 SIMD。

### 暂缓与重新立项条件

- **Decimal / statistics 精确累计**：Fraction 验证通过后再评估；Decimal 另需明确舍入、上下文和陷阱语义。浮点路径仍以当前结果为基线。
- **Float32**：有明确 FFI 或数组需求再开；先写存储/ABI、逐操作舍入和 NaN 口径，不搭 BigInt 版本。
- **AVX2 / 重排浮点归约**：先证明默认关闭的通用 `VECT` 在多个非基准程序稳定、有实测瓶颈；若启用更宽 ISA，必须有 CPU/OS 能力检查与 SSE2 回退，归约重排不得改变默认结果。
- **并发 GC、扩大借用**：先证实 p95/p99 停顿或真实 workload 的引用流量值得做；不复跑已近零收益的通用 RC 对消，不做按基准特化。

### 并行轮次约定（三路同开时）

三条线各自独立工作树（`/tmp/wt-<name>`，从最新 master 分出），**互不修改对方的树**，也不动主线 `build/lead`、`build/release`(0.271 oracle) 与 `docs/`（文档由 lead 在合并时统一写）。每轮自带构建目录 `build/`，闸门在各自树里跑。

| 轮 | 分支 | 交付 | 允许改变的既有 asm |
|---|---|---|---|
| 1 | `erleaf` | lowering 出口释放改用**最终**槽属性；早返回不再漏 `dec`；补最小复现回归 | **允许**：含「早返回在首次堆写之前降级」形状的程序会多出本该有的 `dec`。必须逐条说明预期差异，其余样本仍须逐字节不变 |
| 2 | `fracbig` | `Fraction` 分子/分母升级到 `big`，中间乘积不再回绕；`Decimal` 按同一精确整数内核实现（明确舍入/上下文边界） | 不允许改生成 asm；只动 stdlib |
| 3 | `buildfast` | 削减一次性短脚本的固定构建成本（实测冷 53ms / 热 38ms，其中 `as`≈8ms、`ld`≈9ms） | 不允许改生成 asm；只动编译驱动/链接/缓存层 |

三路都要过同一套闸门（difftest、普通与 ASan 套件、LSan 钉子、check_size），并按各自那一行的 asm 口径自证。lead 逐路复核后再依次合并，**不并行合并**。
## 每轮闸门

1. **两套基线分开**：上一版 `build/lead` 用于新旧汇编与行为比较；`build/release` 是 0.271 语料 oracle，永不重建。比较记录编译/运行退出状态、stdout 和用例分类；双方都编不出来不算“通过”。
2. **完整性**：[`difftest`](../tools/difftest.sh) 零差异 + [`run_tests`](../tests/run_tests.sh) normal（`PYADAMAS_TEST_JOBS=8`）与 ASan（`PYADAMAS_TEST_ASAN=1 PYADAMAS_TEST_JOBS=1`）退出 0 并核对有效用例数 + [`check_size`](../tests/check_size.sh) 零超限。检测泄漏另跑 `detect_leaks=1`：套件默认关闭它。RC/GC 内核至少跑 13/174，扩到 88/92/93/94/119/153/192 并加候选专属针。
3. **无关代码不变**：固定基准清单、编译选项与路径、严格校验生成成功再做 asm `cmp`。默认 `SIMD`、`GC_SECTIONS` 开；通用 `VECT`、`BORROW_OPT`、`TYPE_TAGS`、`LANG_GAPS` 等 opt-in 保持现状。故障修复如确需改变旧 asm，先隔离、再对预期 diff 走显式例外。
4. **性能不靠猜**：同窗、绑核、随机用例顺序、交替 A/B、BURST、多轮中位；先比较输出与退出码再计时，报告 A/A 噪声和样本失败。区分编译器吞吐、编译链接墙钟和运行墙钟，不能把历史 `asm -O2` 吞吐提升当成 `build + run` 的提升。
5. **发布证据**：审最小 diff，保留负面结论，更新对应语言/运行时文档和 [CHANGELOG](../CHANGELOG.md)，候选通过后才在主线重建复验。Win64 没测就标未测，不能以 Linux 通过代替。
