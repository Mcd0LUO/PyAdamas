# 路线图

按「收益 / 风险」排序，不是按「看起来酷」排序。每项都写了验收标准——没有验收标准的需求不算需求。

## 上一轮：对象模型 + 前端去误杀

类在编译期定死布局：对象 = `[vtable 指针][字段 0][字段 1]…`，`p.x` 是一条 `movq 8(%rax), %rax`。方法进 vtable，槽号也是编译期常量；单继承下子类沿用父类的槽位前缀，所以「父类类型装子类实例」能调到子类实现。

实测 2000 万次方法调用 0.09s（CPython 3.88s，43 倍）。

踩到的坑：`ClassInfo` 的字段类型指回 `Type`、`Type` 又用 `shared_ptr` 指回 `ClassInfo`，形成环，ASan 报 2 万字节泄漏。把 `Type::cls` 和 `ClassInfo::base` 都改成裸指针（所有权统一在 `TypeChecker::all_classes_`）之后归零。

第二轮拿 CPython 标准库跑前端基线，才发现类检查把真实代码判死了一大片。按「宁可漏报，不可误杀」放宽：`class A(object)` 认成根类、外部基类标记 `open`、`self.x = ...` 就地补隐式字段、类体语句与多继承降级成「解析了但没建模」（由 `build` 拒绝）、同名方法（`@property` 的 getter/setter）按后者覆盖。详见 [CHANGELOG 0.6.1](../CHANGELOG.md) 和 [compatibility.md](compatibility.md)。

**教训**：每加一层静态检查，都要立刻跑一遍标准库基线。只跑手写用例会以为「检查很准」，实际是悄悄把上万个真实文件判死了。

## 下一步

### 1. 内存管理

**做什么**：引用计数。静态类型下插桩位置是确定的：赋值、传参、返回、容器写入、作用域退出。

**验收**：长循环里反复拼字符串，RSS 不随迭代数增长；`tests/run` 全部通过；能跑一个分配 100 万次对象的程序不 OOM。

**风险**：会改运行时 ABI（对象头加 `refcount`），并牵连闭包（cell 也要计数）、异常对象。所以放在对象模型之后。现在对象头已经是 `[vtable][字段…]`，加引用计数要多一个 8 字节头字段，`py23_obj_new` 和所有 `field.get` 的偏移都要跟着改。

**遗留问题**：循环引用怎么处理。先不做，或者上「试验性」的标记-清扫，只针对容器。

### 2. 闭包

**做什么**：内层函数捕获外层局部变量。两种实现：cell 对象（每个被捕获变量一个堆单元）或整体提升到堆。

**验收**：计数器工厂 `def make() -> ...: n = 0; def inc() -> int: ...` 能正确工作，多个实例互不干扰。

### 3. 补齐构造

优先级从高到低，每项独立，可以随时插入：

| 构造 | 工作量 | 依赖 |
|---|---|---|
| 字典 / 集合字面量与基本操作 | 中 | 哈希函数、开放寻址表 |
| 切片（读） | 小 | 需要新运行时函数 |
| `in` 运算符 | 小 | 列表线性扫、字符串子串 |
| `*args` / `**kwargs` | 中 | 调用约定要支持变长实参 |
| `try/except` | 大 | 展开（unwind）机制 + 异常对象（对象模型已有） |
| 推导式 | 中 | 语法树已经在，降级要生成循环 |
| `with` | 中 | 需要 `__enter__` / `__exit__` |
| 生成器 / `async` | 大 | 协程状态机或独立栈 |
| 装饰器 | 中 | 函数是一等值，主要是语法糖 |
| `import` | 大 | 模块系统、符号解析 |

## 待决策

这些不是「做不做」，是「选哪条路」，需要先定下来再动手：

| 问题 | 选项 | 影响 |
|---|---|---|
| 字符串语义 | 字节串（现状）/ UTF-8 码点 | 改码点则 `len` 变成 O(n)，索引要解码；不改则非 ASCII 的 `len` 与 CPython 不一致 |
| 整数溢出 | 回绕（现状）/ 溢出检查 / 升格 bignum | 检查要每条算术加一条 `jo`；bignum 要一整套运行时 |
| 异常模型 | `exit(1)`（现状）/ setjmp-longjmp / 表驱动 unwind | 影响 `try/except` 的实现方式和生成代码体积 |
| `print` 求值顺序 | 边算边写（现状）/ 对齐 CPython | 只有副作用可见时才看得出来 |
| 许可证 | 未定 | 发布前必须定 |

## 技术债

按「什么时候会疼」排序：

1. **内存只分配不释放**（下一项要还）
2. **Optional 的收窄能力不足**：`x: Optional[str]` 在 `if x is None: ...` 之后、跨语句块或跨函数调用时仍按 Optional 处理，真实代码里有约 6 个文件因此报「Optional 上没有这个方法」。这属于「误杀」，与「宁可漏报」的原则相悖，但修它需要正经的数据流分析
3. **没有优化遍**：常量折叠、CSE、死代码消除一个都没有。IR 的形状是为它们准备的，但一个都没写
4. **`tuple` 与 `list` 表示相同**：现在 tuple 也是可变的动态数组，语义上不严谨
5. **诊断不带列区间**：只指向起点，长表达式不好定位
6. **没有增量重编 Python 源码**：每次 `build` 都是全量编译，没有缓存
7. **浮点变量不进寄存器**：`xmm` 全是 caller-saved，跨调用要自己 save/restore，所以只提升了整数/指针变量。纯浮点循环（5000 万次累加）0.25s，整数同样次数 0.06s。可行的修法是「函数内没有任何调用时」才提升浮点变量，这样不需要保存；代价是 `load.slot` / `store.slot` 要按类型选 `movsd` 而不是 `movq`
